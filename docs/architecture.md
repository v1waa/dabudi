# Архитектура dabudi

`Dabudi.Core` не зависит от WPF и Windows. `Dabudi.Infrastructure` зависит от Core; Windows-специфичные типы отмечены `SupportedOSPlatform`. `Dabudi.App` использует оба проекта и координирует UI через `AppController`. Инфраструктурные сервисы не создают окна.

## Жизненный цикл

`App` владеет единственным экземпляром, контроллером, основным окном и треем. `AppController` владеет всеми инструментами и одним UI-таймером. `OverlayManager` создаёт, перенастраивает и закрывает окна. Команда остановки проходит через одно место, независимо от кнопки, трея или горячей клавиши.

`EffectTimers` и `ElapsedTimer` используют `TimeProvider.GetTimestamp`, поэтому перевод часов не меняет длительности. Остановка секундомера сохраняет результат; следующий запуск обнуляет его. Видимость окна независима от отсчёта. UI-таймер работает, пока нужен отсчёт, и останавливается вместе с секундомером, когда другие таймеры не активны.

`ClickerEngine` сериализует отправку ввода с остановкой. После возврата `Stop` старый исполнитель больше не может послать нажатие. Повторяющийся режим использует периодический таймер, однократный — отменяемое ожидание; оба завершаются через один обработчик. Задержка и её отображение используют `TimeProvider`, отсчёт начинается при вызове команды. Результат содержит идентификатор запуска: запоздалый callback не меняет статус нового запуска. Ошибка отправки завершает текущий запуск и передаётся в интерфейс. Win32-ввод формируется парами down/up; частичная отправка дополнительно освобождает клавишу. Пропущенный ввод по собственному окну имеет отдельный результат и не повторяется.

Закрытие основного окна останавливает инструменты и завершает `Application`. Явное скрытие из боковой панели или трея не закрывает окна инструментов и не меняет их состояние.

## Настройки и сочетания

Настройки проверяются до применения. Новая регистрация сочетаний откатывается при конфликте. Запись JSON происходит через временный файл в той же папке и атомарную замену с `.bak`. Ошибки показываются в интерфейсе и журнале. Запись при захвате клавиши завершается только после получения полноценной комбинации; отмена не меняет модель.

Схема 4 добавляет режим и задержку автокликера. При чтении схемы 3 стандартные цвета и размер прицела 3.0 заменяются значениями 2.5.8; пользовательское оформление сохраняется. Запуск ввода не сохраняется между сеансами.

Клавиша закрытия таймеров регистрируется только при открытом DBD-оверлее. Все сочетания проверяются и при сохранении, и перед запуском автокликера. Для целевой клавиши автокликера запрещается совпадение с основной клавишей любой команды, независимо от модификаторов.

## Мониторинг и оверлеи

Один фоновый исполнитель обслуживает LibreHardwareMonitor и освобождение датчиков. UI не ожидает закрытия драйвера. CPU/RAM читаются через Win32, недоступные значения остаются неизвестными. `nvidia-smi` запускается только при наличии в системной папке или стандартной папке NVIDIA, без оболочки, с ограничением времени. Ошибка основного провайдера не отключает этот резервный путь.

Позиции оверлеев рассчитываются `OverlayPlacement` в физических координатах монитора через Win32. `OverlayManager` заполняет содержимое и учитывает соседние окна до показа. Нативный HWND создаётся невидимым; окно остаётся прозрачным до синхронного завершения layout и размещения в `Loaded`. Нет отложенного переноса через `ContextIdle`. После изменения DPI координаты пересчитываются с фактическим размером окна. Прицел привязан к полному экрану, остальные панели — к рабочей области. Перетаскивание панелей действует в текущем сеансе; после смены настроек или повторного открытия применяется стандартная позиция.

Температуры CPU в LibreHardwareMonitor 0.9.6 требуют PawnIO и доступа к устройству драйвера. `CpuSensorAccess` читает версию из реестра заново и проверяет открытие устройства; CPU-датчики не создаются при отсутствии доступа, чтобы ошибочный нулевой результат MSR не превратился в ложную температуру. Источник: [реализация PawnIo](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/PawnIo/PawnIo.cs).

По явной кнопке `CpuTemperatureSession` запускает тот же EXE в режиме `--cpu-sensor` с UAC. Этот процесс не создаёт UI, горячие клавиши или кликер и только передаёт снимки температуры по случайно именованному каналу, доступному текущему пользователю. Его elevated-токен не передаётся основному приложению. Параметры не допускают произвольных команд, путей установщика или удалённых серверов. Для UAC требуется повышение той же учётной записи; при вводе данных другой учётной записи канал отклонит подключение.

Отсутствующий или старый PawnIO устанавливается только в этом явно запрошенном процессе: закреплённый официальный установщик 2.2.0, SHA-256 `1f519a22e47187f70a1379a48ca604981c4fcf694f4e65b734aaa74a9fba3032`, без ослабления прав устройства. После проверки файл блокируется от записи и замены до завершения установки. Heartbeat не зависит от аппаратного опроса: закрытый канал завершает дочерний процесс, даже если чтение драйвера задерживается. Основное окно никогда не ждёт драйвер при выходе. `--cpu-sensor-smoke` проверяет тот же транспорт с фиксированным тестовым показанием, без установки и UAC.

Автозапуск хранится в `HKCU`, повышение прав не выполняется. Именованные mutex/event обеспечивают один экземпляр в текущем сеансе Windows и восстановление существующего окна.
